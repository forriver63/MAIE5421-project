# 传统方法与主线 pipeline 的统一评估入口

目前包括 Zhang2017 SVD 和 Al-Haj2007 DWT-DCT 的 RGB/32-bit 适配，以及直接调用主线 WAM pipeline 的评估入口。没有修改两篇算法的核心文件，没有新增防越界选块、纠错、重复编码或参数调优。

## 当前完成程度

- 两种传统方法已在公共入口完成各420项测试，结果与迁移前逐条件相同。
- 图片与30条消息一致；30组裁剪坐标与主线源码生成值逐项验证。
- WAM公共入口直接调用 `watermarking.pipeline.embed_image/detect_image`，而不是重写WAM。**尚未实际运行该入口的WAM评估**，当前watermark环境不含完整WAM依赖、上游源码及权重。
- 本次提供的完整结果只有两个传统方法。不得用历史WAM数值填充成“同协议三方法比较”。

## 在终端运行

在仓库根目录、已激活watermark环境时：

```bash
python baselines/test_protocol.py
python baselines/run_pipeline_eval.py --method svd
python baselines/run_pipeline_eval.py --method dwt_dct
```

每次在 `baselines/outputs/` 下新建目录，避免覆盖。`--out` 可指定一个不存在的目录。

WAM由已完成主仓库安装、上游checkout和权重准备的环境运行相同入口：

```bash
python baselines/run_pipeline_eval.py --method wam
```

无需让传统方法安装torch。WAM依赖和权重准备遵循仓库根README。比较时尽量在同一版本NumPy/Pillow、同一机器上重跑；耗时含义是单次嵌入/解码调用，WAM模型加载和PNG写盘不在计时内，不应把当前不同环境的时间直接排名。

## rgb_png32_v1 协议

所有方法：同一512×512 RGB输入、同一32位有效消息 → 嵌入 → uint8 RGB PNG保存重读 → 公共攻击 → 提取 → 公共指标。

公共源文件是 `shared_protocol.py`；各方法旧的 `protocol.py` 只转发导入。旧的 `run_team10.py` 仍用于本方法详细演示，正式统一结果以 `run_pipeline_eval.py` 为准。

| 项目 | 冻结设置 |
|---|---|
| 数据 | 主线commit e43778855daee459079feb6394150355d66d5744的十张PNG，核验文件内容SHA256 |
| 消息 | 每图seed0/1/2，四字节MSB-first；基数20261008 |
| clean | 保存重读后的PNG；统一名称clean |
| JPEG | Q75/50，Pillow，subsampling=2 |
| 噪声 | sigma2/5，8-bit像素尺度，RGB独立噪声，主线同种子规则 |
| 旋转 | ±1/2/5/10度，bicubic，不扩展，黑色填充 |
| 裁剪 | 主线第一种75%面积裁剪，443宽×444高、相同偏移，随后JPEG75，不缩放补回 |
| PSNR/SSIM | 原图与保存后的含水印RGB图；SSIM均匀7×7、样本协方差、K=.01/.03，三通道平均 |
| 整条恢复率 | 32位全正确数/全部30条消息；无法提取也计入分母 |
| BER | 最终有效32位消息，仅对有输出的样本统计；无输出单列，分母明确记录 |
| 错误输出 | 返回消息但与真值不同；与无输出分别统计 |

主线 `experiments/robustness/run.py` 的历史实验使用浮点marked作为clean和部分攻击的起点；其 `raw_ber_matched` 是匹配的局部编码包纠错前BER。**这两点与本协议不同**。主线对外 `pipeline.py` 已输出uint8 RGB图，本协议以这个实际图片接口为共同边界。没有修改历史实验代码或证据。

主线攻击函数使用torch归一化张量，本协议使用NumPy/Pillow数组操作；参数、种子、几何定义对齐，不声称与历史torch路径逐像素完全一致。新入口中三方法共用同一攻击实现，排除该差异。

WAM的有效32位经过编码/重复后承载256位；传统默认承载32位。三者失真预算也未匹配。本轮只能作为明确这些区别的系统级开发检查，不是等失真/等冗余的模型优劣证明。没有新增定位指标或无水印误报率：传统提取器并不具备经过校准的存在性检测。

## 方法适配和已知限制

SVD：论文空间域近似更新，4×4块，delta12，按原图最大奇异值排序选择32块，保存块位置作为旁信息；RGB亮度适配，关闭方形水印Arnold打乱。本轮诊断浮点30/30，像素范围截断后25/30，整数PNG24/30。保留这种行为，没有为提高结果另改选块规则。

DWT-DCT：HL1→HL2、Haar、4×4 DCT、七个指定中频位置、PN seed2007、alpha20、32位无重复。小波族、中频掩码、PN细节及alpha是明确的工程选择；RGB亮度、稀疏32位布局属于项目适配。浮点即有45/960位误码，具体原因尚未完全确认，不能声称论文报告性能已被复现。

两种方法都在Y=.299R+.587G+.114B上嵌入，将亮度残差加回三通道；输出裁剪并np.rint量化。原图/真实消息不进入提取接口；SVD依赖的选块旁信息须在报告中披露。未实现裁剪后盲同步，不能把不支持的结果说成已经证明原论文对任意裁剪必然失效。

## 评估同学需要做什么

用公共入口分别运行三种方法即可得到同一schema，无需使用传统方法的内部packet结构。先在准备好的WAM环境运行`--method wam`，再确认依赖版本、画质预算和正式数据集；不要从历史结果复制WAM分数。当前十张图是开发筛查集，不是独立大规模测试集。

数据准备已允许自己的分支继续提交：固定的是输入文件所属版本及其内容，而非要求当前HEAD永远停在主线旧提交。
