# 从运行命令到研究逻辑

## 1. 先区分三种流程

- **使用流程**：输入图片和一个 32 位整数 → 嵌入 → 保存 → 提取。入口是 `wm` 或 Web API。
- **当前实验流程**：调用 `experiments/` 中的独立脚本，测量某个问题，并将结果写入实验自己的目录。
- **原始研究流程**：先写判定门槛，测量，分析失败原因，再决定下一阶段。四个 `validation_*` 目录记录的是这条研究链，不是四个必须依次加载的运行组件。

没有训练阶段：使用官方预训练 WAM，研究工作集中于消息编码、区域布局、盲检测后的解码及评估。当前工程没有把原始研究的全部阶段自动串成一键流程。

## 2. 当前怎么运行

在仓库根目录执行，首次安装：

```sh
python3.10 -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"
```

已有环境只需 `source .venv/bin/activate`。官方 WAM 源码、固定提交及权重的准备命令见根目录 README；默认位置为 `validation_wam_20261007/watermark-anything/`，也可通过 `WAM_PATH` 指向其他目录。权重和环境不提交到 Git。

先验证编码，再做一张图的文件往返：

```sh
python -m pytest
wm embed input.png marked.png --payload 0x12345678
wm detect marked.png --json
```

测试包括全部 65,536 个 BCH 消息、最小距离、误码模式、全部 2,048 个 ID/字节组合，以及 MDS 的 70 种四包子集。部分穷举耗时明显；这些测试验证编码代数，不证明 WAM 对任意图片都鲁棒。

`embed` 会将输入转换成 RGB，并居中裁剪/缩放至 512×512；输出不会保持任意输入尺寸。建议保存 PNG，避免最初保存就额外引入 JPEG 攻击。`detect` 不再裁成 512×512，裁剪攻击后的像素可直接进入检测。例子成功时返回十进制 `305419896`；`status`、`payload`、有效 ID 数及冲突 ID 用于检查是否恢复成功。

启动接口可视化操作页：

```sh
python -m uvicorn watermarking.web:app --host 127.0.0.1 --port 8000
```

浏览器打开 `http://127.0.0.1:8000/docs`。`/embed` 上传图片和整数，返回 PNG；`/detect` 上传图片，返回恢复结果；服务启动时只加载一次模型。

当前实验入口：

| 命令 | 实际执行内容 | 输出目录 |
|---|---|---|
| `python experiments/baseline/run.py` | 2/4/8 区域干净图片筛选，门槛失败即停止 | `experiments/baseline/results/` |
| `python experiments/inner_ecc/run.py` | 四区域 BCH 干净图片恢复、质量和门槛 | `experiments/inner_ecc/results/` |
| `python experiments/hierarchical/run.py` | repetition 与 MDS 的干净图及配对盲裁剪比较 | `experiments/hierarchical/results/` |
| `python experiments/ablation/run.py` | repetition/MDS 在 clean、JPEG75 下的比较 | `experiments/ablation/results/` |
| `python experiments/robustness/run.py --output-dir output/run-01` | 最终 repetition 方案的 14 条件评估及负对照 | `output/run-01/results/` |
| `python experiments/robustness/finalize.py --output-dir output/run-01` | 读取 CSV，汇总指标、绘图、生成判定 | 同一目录的 `results/`、`figures/` |

每个实验自行准备十张图并加载模型，无需先跑 baseline 才能跑 robustness。前四个脚本会覆盖各自生成的结果。鲁棒性脚本默认拒绝已有测量 CSV：换新 `--output-dir` 才是重新测量；使用 `--reuse` 是显式复用，检查 420/3360/10 行，跳过推理。它不验证旧文件与当前源码、权重是否相同，也不是中断续跑。

只想重新汇总已有默认结果：

```sh
python experiments/robustness/run.py --reuse
python experiments/robustness/finalize.py
```

## 3. 一张图片的完整算法链

### 嵌入

1. 32 位整数按大端顺序拆成四个字节 A、B、C、D。例如 `0x12345678` 拆成 `0x12, 0x34, 0x56, 0x78`。
2. 八个物理区域依次保存 `[A,B,C,D,D,C,B,A]`，排列为两行四列。两个副本分散到不同位置。
3. 每个区域的数据包是 `ID[3] + 字节[8] + CRC[5]`，总计 16 位。ID 表示物理区域 0–7，CRC 校验 ID 和数据。
4. BCH(31,16) 把 16 位编码为 31 位，再追加一个整体偶校验位，适配 WAM 的 32 位消息接口。
5. 对同一张原图执行八次官方 WAM 嵌入，每次只取对应 mask 区域内的像素，合成为最终图片。区域外保持原图像素。

八个固定矩形各 110×205 像素，在 512×512 画布上有间隔。最终嵌入预算是 8×32=256 位，有效全局信息是 32 位，因此有效信息占比为 1/8。

### 盲提取

1. WAM 预测每个像素的水印存在概率和消息位。
2. DBSCAN 根据消息输出聚类，得到候选区域及各自的 32 位消息；mask 阈值 0.5，epsilon=1，min_samples=500。
3. BCH 修复保证范围内的误码。扩展码可纠正最多三位错误，包括整体校验位；四位错误被拒绝；五位及以上可能误纠正。
4. CRC 检查 BCH 解出的 16 位消息，失败则作为擦除。CRC 不能保证所有错误都被发现，也不是密码学认证。
5. 同一 ID 出现不同有效字节时，擦除该 ID。根据 ID 将区域映射回 A/B/C/D。
6. 每种源字节至少有一个有效副本且副本不冲突，才输出完整 32 位整数；两个副本均缺失则恢复失败。

“至少收到四个包”对于 repetition **不充分**：四个包可能只覆盖 A、B。MDS 在四个不同 ID 的符号均正确时，可以从任选四个恢复；错误但 CRC 合法的符号仍可能破坏恢复。MDS 用多余方程检查一致性，不能把它理解为无条件修复错误包。

检测器不读取原图、真实 payload、嵌入 mask 或裁剪坐标。评估器在检测完成后使用这些真值，匹配区域并计算误码；不能把评估用的真值匹配当成部署时的解码步骤。早期 baseline 用真值消息的汉明距离做匹配；后续主要采用 mask 空间重叠做评分匹配，因此诊断指标也不能完全不加区分地横比。

## 4. 原始研究为什么这样推进

### 阶段 0：早期 DWT/DCT pilot

`EXPERIMENT_PLAN.md`、`src/pilot.py`、`src/offline_backend.py`、`src/build_report.py` 属于旧 pilot。它研究 64 位有效信息和其他后端，不是最终 WAM 的 32 位方案。它不能作为 WAM 的测量结果，也不属于当前运行必经步骤。

### 阶段 1：先验证官方 WAM 是否能可靠恢复多个局部消息

证据：`validation_wam_20261007/`。

十张公开样例图，每张三个 payload seed，先放两个区域，再四个，只有通过门槛才扩展八个。两区域要求包恢复率 ≥95%、整图两包全对 ≥90%；四区域要求包恢复率 ≥90%、四包全对 ≥80%。

原记录四区域恢复 112/120 包，但整图全对仅 22/30，即 73.3%，未达到 80%。八个失败包都被定位到了，错误集中在 1–3 位。因此结论是当前原始消息方案 NO-GO，后续未按原计划直接推进，而是先解决局部误码。

这一步区分了两个问题：区域完全找不到，还是区域找到了但少数位错。只有后者适合直接尝试内部纠错码。

### 阶段 2：BCH 能否修复局部误码，裁剪后还会发生什么

证据：`validation_wam_inner_ecc_20261008/`。

先验证 BCH 代数，再用相同图片/种子和四个区域，将每区域的 16 位有效消息保护成 32 位。受保护实验中，WAM 原始输出有 115/120 个码字完全正确；BCH 解码后 120/120 个有效消息正确。

注意：115/120 是这批 **BCH 码字在纠错前** 的结果，112/120 才是上一阶段未编码实验；不同实验的消息内容和有效容量不同，不应写成完全同载荷的 112→115→120 性能递增链。

然后做 10 图×3 seeds×2 裁剪面积×3 长宽比=180 个盲裁剪，每图四区域，共 720 个区域样本。75% 和 50% 指保留面积，不是宽高各保留相同比例。长宽比分别为 1:1、4:3、3:4，随机偏移由固定种子决定。

BCH 后，保留了至少 75% 自身面积的区域大多可恢复；但出现 3+5=8 个静默错误，8/720≈1.11%，超过预先声明的 1% 门槛。多数失败与区域被裁掉有关，但不能把所有坏包都当成可靠的“缺失”。因此转向 CRC 过滤，而不是立即宣布成功。

### 阶段 3：把坏包过滤成擦除，再比较外层恢复策略

证据：`validation_wam_hierarchical_final_20261008/`。

先在四区域加入 ID+CRC：720 个裁剪区域样本中，510 个正确、210 个擦除、0 个静默错误；225 个大部分保留的区域中恢复 216 个，即 96%。这支持“先检错，再处理擦除”的方案，但样本中零错误不代表理论上不可能误接收。

随后独立测试八区域：30/30 图至少有四个正确有效包，平均 7.7 包，质量约 41 dB PSNR、0.98 SSIM，240 个区域中仍出现 1 个静默错误。达到预设筛选门槛后，才比较外层方法。

MDS 先验证 GF(256) 代数和全部 C(8,4)=70 个四行子集。公平比较时，两种方法都用相同的 32 位全局 payload、八区域、CRC/BCH、WAM 强度、图片、种子和裁剪窗口；只改变每个区域的符号值。每种方法有 180 个裁剪样本，共 360 次裁剪检测，构成 180 对。

| 保留面积 | repetition | MDS |
|---|---:|---:|
| 约 75% | 85/90 | 81/90 |
| 约 50% | 76/90 | 81/90 |
| 合计 | 161/180 | 162/180 |

MDS 总共只多恢复一个，提升约 0.56 个百分点；75% 面积条件下反而降低 4.44 个百分点。原门槛要求合计至少提高 10 个百分点、每个面积不退步，并同时满足画质与静默错误约束。因此没有采用 MDS，最终保留更简单的 repetition。MDS 的理论四包可恢复性质并不能保证它在实际图像检测信道上优于空间重复。

### 阶段 4：冻结最终方案，测量鲁棒性的边界

证据：`validation_wam_final_robustness_20261008/`。

此时固定 WAM+BCH+CRC+repetition，不再在最终评估里挑最好的外层方法。10 图×3 seeds=30 张标记图，各做 14 个条件：clean、JPEG75/50、noise2/5、八个旋转角度（±1/2/5/10 度）、一次约 75% crop+JPEG75。总计 420 案例、3,360 条区域评分，再加十张未嵌入原图负对照。

噪声 σ 按 8 位像素尺度定义；旋转使用 bicubic、不扩画布、黑边填充；组合攻击先裁剪再 JPEG。clean 直接检测内存张量，而命令行保存 PNG 再检测包含 8 位量化，所以两者不必得到完全相同的结果。

历史结果：clean 29/30，noise2 30/30，noise5 28/30，JPEG75 24/30，JPEG50 12/30，±1 度各 28/30，±2 度各 27/30，±10 度仅 6/30 和 3/30，crop+JPEG75 为 12/30。因此结论是 LIMITED。

小旋转合并恢复率 110/120≈91.7%，未触发历史协议中预设的逆角度搜索。当前新脚本也没有实现搜索模块；如果新实验触发门槛，会明确停止，而不是把搜索当成已运行。

## 5. 指标应该怎么读

- **全局精确恢复率**：全部 32 位都正确才算成功，是最终主要指标。
- **局部包恢复率**：用于解释全局失败，分原始消息、BCH 后、CRC 后；各阶段容量不同。
- **擦除**：未检测到或被拒绝的包；**静默错误**：错误但被接受的包。外层擦除码依赖后者足够少。
- **BER**：只对真值匹配成功的包统计，分母是匹配包数×32；必须同时看缺失数量，低 BER 不意味着高全局恢复率。
- **PSNR/SSIM**：比较干净原图和干净标记图，描述嵌入失真；不是受攻击后的恢复率。
- **负对照**：十张未标记图片没产生完整假 payload，只是小规模 sanity check。

30 个图/seed 案例来自十张图，同图三个 seed 不等于三张独立图片；420 个攻击案例也不是 420 张独立图片。该集合用于方案筛选，历史各阶段复用它，不能视为独立留出测试集上的泛化结论。

## 6. 为什么保留四个 validation 目录

它们保存四次不同决策的证据：原始局部误码 → BCH 后的静默错误 → CRC/外层选择 → 最终鲁棒性边界。只留下最终图表，读者无法追溯为什么加入 BCH、为什么还需要 CRC、为什么没采用 MDS。

建议保留 protocol、report、关键 CSV/JSON、必要图表，并将新实验输出放在 `experiments/` 或独立 `output/` 下。源码统一维护在 `src/watermarking/` 和 `experiments/`。不必保留重复运行环境、下载权重、临时日志或重复输入图片。

保留这些目录是研究可追溯性要求，不是运行算法的技术要求。唯一当前默认路径耦合是 WAM checkout 位于第一个目录下；设置 `WAM_PATH` 后可解除。未来可以统一搬到 `archive/`，但必须同时修正文档链接和默认路径，当前没有为整理外观而搬动历史证据。

旧报告中提及的脚本、RUNBOOK、机器环境、日志可能已移除或忽略，不能再按那些旧命令执行。完整历史代码应查看原始提交；当前迁移范围和已知差异见 [RESEARCH_HISTORY.md](RESEARCH_HISTORY.md)。
